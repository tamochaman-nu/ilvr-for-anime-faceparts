# アニメ目DDPM × ILVR: 実写の目 → アニメ調の目

アニメの目の画像 (32×32) だけで学習した無条件 DDPM (以下「目DDPM」) を、ILVR (Choi et al., ICCV 2021) で
実写の目のクロップに条件付けして、アニメ調の目を生成する。ILVR の公式実装 (jychoi118/ilvr_adm) を土台にし、
公式実装の既存ファイルは変更せず、目DDPM 用の処理を新規ファイルで追加している (変更の記録は `patches/README.md`)。

## 1. 使い方

```bash
cp .env.example .env                       # データセット・チェックポイントのパスを合わせる
docker compose build
docker compose run --rm verify-ilvr        # 自作 ILVR ループの検証 (V1〜V7)
docker compose run --rm make-ref-lists     # 参照画像の選別とリスト (lists/)
docker compose run --rm ilvr-eye           # 変換 (既定: N=8, range_t=20, 参照画像 16 枚)
docker compose run --rm -e DOWN_N=16 -e RANGE_T=40 -e SEEDS=0,1,2 \
  -e REF_LIST=lists/real_eye_grid16.txt ilvr-eye   # 条件は環境変数で (一覧は scripts/run_ilvr_eye.sh)
docker compose run --rm phase3             # Phase 3 の総当たり・評価・グリッド (outputs/phase3/)
docker compose run --rm fit-color-stats    # Step 3: 色の写像の統計 (lists/color_stats.json)
docker compose run --rm step3              # Step 3: 改善案の比較 (outputs/step3/)
docker compose run --rm lr-masked          # 左右別の目DDPM x マスク済みの目で比較資料の条件 (outputs/lr_masked/)
docker compose run --rm eval-ilvr          # 任意の実行結果の評価 (-e RUN_DIRS=... -e OUT_CSV=...)
# 推奨設定での変換 (6 節): 色の写像 + 縮小 3x3
docker compose run --rm -e COLOR_TRANSFER=lab_meanstd -e DOWN_SIZE=3 -e RANGE_T=40 ilvr-eye
```

出力ディレクトリには `refs/` (モデルに渡した参照画像)、`samples/<参照画像名>_seed<S>.png`、`run.json`
(引数・train.cfg・参照画像と出力の対応・実行時間・VRAM) が入る。乱数はサンプルごとに「シード + 参照画像の
ファイル名」から決まるので、バッチの組み方や参照画像の組を変えても同じ参照画像・同じシードの結果は変わらない。

## 2. 流用可否の判定 (Phase 1): Plan B

`diagnostics/check_ilvr_compat.py` (結果: `diagnostics/outputs/phase1/check_ilvr_compat.json`)

| 項目 | 結果 | 根拠 |
|---|---|---|
| C1 公式の UNetModel にチェックポイントが読めるか | 不合格 | 目DDPM は EDM2 の magnitude-preserving UNet (`MPUNetModel`)。キーの重なりなし (公式 386 キー / チェックポイント 155 キー) |
| C2 公式モデルとの出力一致 | 実行不可 | C1 不合格のため |
| C3 拡散過程 (betas・alphas_cumprod・timestep_map・p_sample 5 ステップ) の一致 | 合格 | 公式と学習フォークで差 0.0 (間引きなし / 100 ステップ) |
| C4 無条件生成がアニメの目になるか | 合格 | 公式とフォークの拡散過程で出力が完全一致。彩度 0.281 / ラプラシアン分散 0.054 (学習データ 0.249 / 0.060) |

→ 拡散過程とサンプリングは公式実装をそのまま使い、モデルだけ学習フォークの `unet_mp.py` (そのままコピー) を使う。
`MPUNetModel.forward` は `ref_img` を受け取れないので、ILVR のループは `guided_diffusion/ilvr_eye.py` に書き直した
(公式のループとビット単位で一致することを V2 で確認)。

ILVR の補正は公式と同じく、間引き後のステップ i について i > range_t のときだけ
`x ← x − up(down(x)) + up(down(q_sample(y, t)))` (`t_ref=t-1` で論文の Algorithm 1 と同じ番号にもできる)。

## 4. 評価の方法

- **参照画像**: 実写の目 135,428 枚から、切り出し時のスコア (`parts.jsonl`) で眼鏡 (`glasses ≥ 0.05`)、
  閉じた目・細めた目 (`eye_px < 0.5`)、隠れた目 (`vis < 0.9`)、横向き (`|yaw| > 30°`) を除いた 93,899 枚から、
  左右半数ずつ 1000 枚 (`lists/real_eye_eval1000.txt`)。グリッドはその中の 16 枚 (`lists/real_eye_grid16.txt`)。
- **各条件 3 シード = 3000 枚**。KID はアニメ目の学習データ 10,000 枚 (`lists/anime_eye_kidref10000.txt`) と比較
  (サブセット 1000 枚 × 100 回)。
- **指標** (`guided_diffusion/ilvr_metrics.py`):
  - 参照画像との対応: `lowfreq_rmse_8` / `_4` (8×8・4×4 に縮小して比べた RMSE。条件によらず同じ大きさで測る)、
    LPIPS (AlexNet、64px に拡大)、`delta_e_eye` / `_img` (CIELAB の平均色の差。目の付近の楕円 / 画像全体)
  - アニメらしさ: KID、彩度、ラプラシアン分散 (線のくっきりさ)、輝度
  - その他: `seed_mad` (同じ参照画像のシード違いの出力どうしの平均絶対差 = 多様性)、時間、VRAM
- **比較の基準**: アニメの holdout (KID ≈ 0、下限)、実写の参照画像そのもの (KID 0.41、上限)、無条件生成 (`DOWN_N=0`)

### 所見

1. **down_N がアニメらしさと参照画像の保持のトレードオフの主な軸**。N を大きくするほど KID は下がり
   (N4 0.06〜0.15 → N32 0.018)、参照画像との対応 (LPIPS・低周波 RMSE・目の付近の色差) は失われる。
   - N4: 実写の陰影がほぼそのまま残り、線だけアニメ風 (ラプラシアン分散 0.015 は実写の 0.013 に近い)。
   - N8: 中間。グリッド (16 枚 × 3 シード、目視の概数) ではアニメの目として読めるのは約半数で、残りは前髪・暗い塊・
     眼鏡のフレーム状の線 (約 1 割) になる。
   - N16: 約 7 割がアニメの目として読めるが、目の付近の色差が 15 と大きく、虹彩の色・形の対応は弱くなる。
   - N32: 平均色だけが対応し、目の位置・大きさはシードで大きく変わる (seed_mad 0.41)。
2. **range_t は、その N の縮小サイズの成分にしか効かない**。N8 で range_t を 0→40 にすると 4×4 RMSE は
   0.003→0.076 と緩むが、8×8 RMSE は 0.153→0.177 とほとんど変わらず、同じシードでは構図もほぼ同じ。
   KID は少し下がる (0.039→0.027)。N16・N32 ではほぼ効かない。
3. **すべての ILVR の出力が、実写の平均色 (輝度 0.495・彩度 0.37〜0.39) をそのまま受け継ぐ**。アニメの学習データは
   輝度 0.65・彩度 0.25 で、無条件生成もそれに近い。平均色しか拘束しない N32 でも KID は無条件生成の約 6 倍
   (0.018 対 0.003) で、**KID の差の大きな部分は「実写の肌の色・暗さ」そのもの**と考えられる。
4. **参照画像を選別しても、眼鏡・前髪の誤生成は残る**。眼鏡を掛けていない参照画像からも、暗い眼窩や影が
   フレームや前髪として描かれる (N4・N8 で多い)。実写とアニメで低周波の形が違うこと (目の付近の輝度:
   実写 0.32 / アニメ 0.56、`diagnostics/outputs/dataset_lowfreq/`) が原因という見立てと合う。
5. **線のくっきりさが足りない**。ラプラシアン分散は ILVR で 0.015〜0.036、無条件生成で 0.046、学習データで 0.060。
   条件付けを強めるほど写真のなめらかな陰影が入り、線が鈍る。
6. **実装の選択肢の差は小さい**。t−1 は t より KID がわずかに良い (0.032 対 0.033、シード間の標準偏差 0.0002)。
   interpolate は 4×4 RMSE が大きく (0.046 対 0.040)、補正が射影にならないぶん拘束が甘い。既定は t・Resizer のままでよい。
7. **候補の動作点**: 参照画像の目の色・形をある程度残すなら N8 rt40 (KID 0.027 / LPIPS 0.26)、
   アニメらしさを優先するなら N16 rt40 (KID 0.021 / LPIPS 0.29)。どちらも誤生成が残るため、6 節の改善が要る。

## 6. 改善案の比較 (Step 3)

`docker compose run --rm step3`。Phase 3 と同じ参照画像 1000 枚 × 3 シード・同じ指標で、range_t=40 に固定して比べた
(`outputs/step3/metrics.csv`、グリッドは `grid_a_color.png` / `grid_b_mask.png` / `grid_c_size.png`)。

- **a. 色の写像** (`--color_transfer`): 参照画像を CIELAB のチャネルごとに、実写の目の色の分布からアニメ目の色の
  分布に写してから ILVR に渡す。写像はデータセット単位で固定 (画像ごとに合わせないので、参照画像どうしの色の
  違いは相対的に残る)。統計は評価に使う画像を除いた各 5000 枚から求めた (`scripts/fit_color_stats.py`):
  L\*a\*b\* の平均 実写 (51.4, 14.1, 14.5) → アニメ (66.1, 9.3, 7.0)、標準偏差 (20.7, 7.4, 10.1) → (25.0, 10.9, 13.7)。
  `lab_meanstd` (平均と標準偏差を合わせる一次変換) と `lab_quantile` (分位点を合わせる) を比べた。
- **b. マスク付き ILVR** (`--mask_dir`): 切り出し時の目の楕円マスク (`eye_mask/`) の部分だけ参照画像の低周波に
  合わせる。補正量にマスクを掛けるだけ (`multiply`: `x ← x + m·(lp(y) − lp(x))`) では、縮小がマスクの外も
  含めて平均するため外のずれをマスク内の画素で埋め合わせようとして値が飽和し、白黒のベタ塗りに崩れる。
  参照画像のマスクの外を現在の x で置き換えてから補正する `composite` (`x ← x + lp(m·(y − x))`) にした
  (補正量がマスク内の差の低周波なので発散しない)。膨張 0 / 3 画素。
- **c. 中間の縮小サイズ** (`--down_size`): 6×6 (N4 と N8 の間)、3×3 (N8 と N16 の間)。
- **d. 色の写像の変形**: `lab_meanstd_l` (L\* だけ平均と標準偏差、a\*b\* は平均だけ)、`lab_mean` (平均だけ)。
- **e. 代理画像** (`--proxy ellipse`, `guided_diffusion/ilvr_proxy.py`): 実写の陰影を渡さず、目の楕円 (マスクの
  モーメント)・虹彩の位置 (暗い画素の重心) と色・肌の色だけを、アニメの目に近い図形 (白目・虹彩・瞳孔・
  ハイライト・まぶたの線、一様な肌) で描いて参照にする。色は `lab_meanstd_l` で写した参照画像から取る。
  `--proxy_blend` で色を写した実写と混ぜる (1.0 = 代理画像だけ、0.5 = 半分ずつ、0 = 従来の方式と同じ: V8)。

### 所見 (Step 3)

1. **色の写像は、どの N でも KID を約半分〜3 分の 1 にする** (N4 0.056→0.032、N8 0.027→0.012、N16 0.021→0.006)。
   輝度・彩度はアニメの学習データ (0.65 / 0.25) にほぼ一致する。一方、写した参照画像との構造の対応
   (8×8 RMSE・ΔE) は写さない場合の加工前の参照画像との対応とほぼ同じで、**構造の保持をほとんど犠牲にせずに
   色の分の差を取り除ける**。Phase 3 の所見 3 (KID の差の大部分は平均色) を裏付ける。
   写像した参照画像そのものの KID は 0.33 と高いままなので、効いているのは「アニメの色にした実写」が
   アニメらしいからではなく、ILVR が渡す低周波の色がモデルの分布の内側に入ったからと考えられる。
   線のくっきりさ (ラプラシアン分散) も上がる (N8 0.026→0.039。無条件生成 0.046)。
2. `lab_meanstd` と `lab_quantile` の差はほぼ無い。単純な meanstd でよい。目視では、実写の青みがかった影が
   a\*b\* の標準偏差の拡大で強まり、青や紫の影・眼鏡のような帯になる例がある (グリッド `grid_c_size.png` の 4 列目など)。
3. **中間の縮小サイズ**: 3×3 は色を写さない場合 N8 とほぼ同じだが、色の写像と組み合わせると N8 より KID が小さく
   (0.010 対 0.012)、写した参照画像との LPIPS も同程度 (0.270 対 0.276)。6×6 は N4 と N8 の間に収まる。
   KID 対 LPIPS (写した参照) の上で、N4 → S6 → S3 → N16 (いずれも + meanstd) が連続した選択肢になる。
4. **マスク付き ILVR は改善にならなかった**。目の外が自由になるので KID は下がるが、LPIPS・8×8 RMSE が
   大きく悪化し (目の位置・大きさが参照画像からずれる)、同程度の KID なら色の写像 + 縮小サイズの調整の方が
   参照画像との対応が良い。目視でも、眼鏡のような縁は膨張したマスク内 (目の周りの陰影) から生じており、
   マスクでは除けない。マスクの外も弱く拘束する (例: 外は N=32) などの変形は試していない。
5. (a〜c 時点の) 動作点の推奨は **S3 (3×3) + meanstd、range_t=40** (KID 0.010 / 写した参照との LPIPS 0.27)。参照画像の
   構造をより残すなら S6 + meanstd、アニメらしさを優先するなら N16 + meanstd。

6. **色の写像の変形 (d)**: KID は meanstd / meanstd_l / mean で誤差の範囲 (0.010〜0.011、サブセット間の標準偏差
   約 0.001)。meanstd_l は目視で青や紫の帯がやや弱まり、目の付近の色差もわずかに小さいが、彩度は 0.21 と
   アニメ (0.25) よりやや低い。大差はないので、代理画像には meanstd_l を組み合わせた。
7. **代理画像 (e) は、KID では悪化するが、目として読める割合は大きく上がる**。
   - KID は代理画像だけ (1.0) で悪化する (N4 0.067、色の写像だけの N4 0.032)。代理画像の肌は一様で、髪・影・
     質感が無いため、出力も背景が平板になり、アニメの目の切り出し (髪や影を含む) の分布から外れる。
     実写と半分ずつ (0.5) では改善する (N4 0.028、S6 0.022、S3 0.013)。
   - 一方、目視 (`grid_e_proxy.png`, `grid_e_proxy_seeds.png`、16 枚 × 3 シード、私 1 人による概数) では、
     アニメの目として読める割合が N4 + 代理画像 1.0 でほぼ全数 (約 46/48)、0.5 で約 40/48、S3 + meanstd_l
     (代理画像なし) で約 30/48。眼鏡のような縁はほぼ消える (0.5 では一部残る)。
     KID はこの「目として読めるか」をほとんど反映していない。
   - 写した参照との対応 (8×8 RMSE 0.09〜0.10、目の付近の色差 5.4〜5.9) は、代理画像との対応としては良く、
     目の位置・大きさは保たれる。虹彩の色は N4 の低周波ではぼけて、シードによって変わる。
   - **多様性の懸念は当たっている**: N4 + 代理画像 1.0 は、シードを変えても構図が同じ (中央の目・一様な肌・
     髪なし) で、seed_mad も下がる (0.139、N4 0.155、S3 + meanstd_l 0.267)。0.5 では背景に髪などが戻る。

## 7. 左右別の目DDPM とマスク済みの目 (2026-11-20)

左右の目を別々に学習した `anime-eye32-mp64-left` / `-right` (設定は `ddpm/train.cfg`。`anime-eye32-mp64.cfg` と
同一: IMAGE_SIZE=32 (1 行目)、LEARN_SIGMA=True (9 行目)、DIFFUSION_STEPS=1000 (23 行目)、NOISE_SCHEDULE=cosine
(24 行目)) と、ランドマークの楕円の外を白で埋めたマスク済みの目 (`crop_parts.py --split_eye_sides` の
`eye_{l,r}_masked/`) で、代理画像の有無の比較をやり直した (`scripts/run_lr_masked.sh`)。

- 参照画像の名前 (`<元の名前>_l.png`、画像の左側の目が l) に応じて left / right のモデルを使い分ける
  (`--model_path_l` / `--model_path_r`)。左右別のフォルダは `{side}` を含むパスで読む (`ilvr_eye.image_path`)。
  参照画像の名前と乱数は Phase 3 / Step 3 と同じ。
- 色の写像の統計は白い背景を除いた目の部分だけで求め (`lists/color_stats_masked.json`)、写像も目の部分だけに
  適用する (`--color_mask_dir`)。
- KID の比較対象は、マスク済みのアニメの目 (左右別) の `lists/anime_eye_kidref10000.txt` の画像。比較対象が
  違うので、KID の値は 5・6 節とは直接比べられない。

結果と所見は `docs/20261119_proxy_comparison/proxy_comparison.md` (git 管理外) にまとめた。要点:
眼鏡・前髪の誤生成はマスクでどの条件でも消える。N8 より粗い縮小では目の輪郭が丸や不定形に崩れる。
KID の最小は S3 + 色の写像 (0.005)。N4 + 代理画像は目の形を保ち、目として読める割合が最も高い (約 46/48)。
色の写像と代理画像では、目の部分の彩度がアニメより低くなる (0.13〜0.17、アニメ 0.24)。
